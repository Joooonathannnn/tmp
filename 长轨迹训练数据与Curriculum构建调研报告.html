长轨迹训练数据与 Curriculum 构建调研报告

面向超长运筹 / Agent 决策轨迹，重点研究三个问题： 如何从已有失败或低分轨迹中选择值得训练的中间状态； 如何从中间状态重新生成具有学习价值的轨迹； 如何依据当前模型的 rollout 表现构建动态 Curriculum。

1. 调研问题与核心结论

当前场景的特点是：单条轨迹可能包含数百轮决策和数百万甚至数千万 Token； 已有大量失败轨迹，以及“最终能够完成但得分较低”的轨迹； 环境允许恢复到某个中间状态，并从该状态继续求解。 最终目的不是单纯分析失败原因，而是把这些历史轨迹转化为真正可用于模型训练的数据。

当前设想可以概括为：

失败 / 低分长轨迹 → 找高影响关键状态 → 从关键状态重新 rollout → 得到多条不同质量的 continuation → 根据 rollout 分布估计状态难度 → 将高质量 / 低质量 continuation 转换为训练数据 → 按难度组织 Curriculum。

目前没有发现一篇论文完整覆盖这条链路，但近两年的多篇工作分别解决了其中不同环节。 最相关的方法包括：

论文 年份 / 来源 主要解决的问题 轨迹数据如何产生 相关度
CRPS ACL Findings 2026 长 Horizon 下大量 rollout 全失败，缺少有效 RL 信号 保存成功轨迹，从其中间 suffix state 恢复，再由当前 policy 重新 rollout ★★★★★
Watch Every Step / IPR EMNLP 2024 只有最终 reward，无法知道中间 action 是否正确 沿 expert trajectory 到某一步，再从该状态进行 Monte Carlo rollout ★★★★★
PaTR 2026 Preprint 每条轨迹从头 rollout 浪费大量预算 在高价值 intermediate state 上 branch，形成 rollout tree ★★★★★
AgentRx Microsoft Research 2026 长失败轨迹中真正失败起点难定位 不生成新轨迹；逐步检查已有轨迹，定位 critical failure step ★★★★★
DAPO NeurIPS 2025 全对或全错 rollout group 没有有效 advantage 同一任务多次 rollout，根据正确率动态过滤极端 group ★★★★☆
SPEAR ICLR 2026 探索与历史成功轨迹利用之间如何平衡 将历史高优势轨迹存入 replay buffer，并持续 self-imitation ★★★★☆
AgentGym-RL / ScalingInter-RL 2025 直接训练长交互 Horizon 太困难 逐步增加允许的 interaction rounds ★★★☆☆

2. CRPS：从成功轨迹中间状态重新开始，并动态调节难度

论文： CRPS: Curriculum Replay via Progressive Suffixes from Successful Trajectories for Long-Horizon LLM Agents

2.1 问题背景

CRPS 针对的是 long-horizon Agent reinforcement learning。 在这类任务中 reward 往往只在最终任务完成时给出，因此训练初期很容易出现： 

同一个任务 rollout 8 次：

0 0 0 0 0 0 0 0

对于 GRPO 一类依赖组内 reward 差异计算 advantage 的方法， 如果同组轨迹全部失败，则很难获得有区分度的训练信号。 相反，如果任务太简单： 

1 1 1 1 1 1 1 1

同样没有有效的组内差异。 因此 CRPS 的核心目标，是让训练中的任务持续处于“不是全会，也不是完全不会”的区间。

2.2 Success Buffer 保存什么？

CRPS 仍然先让当前 policy 从正常初始状态完成完整 rollout。 如果偶然产生一条成功轨迹，就将其保存。 一条成功轨迹可以写为：

τ = (x, z, T, {(o₀,a₀), (o₁,a₁), ..., (oT−1,aT−1)})

其中：

  • x：任务 instruction；
  • z：环境初始化或能够恢复环境的信息，例如随机 seed；
  • T：成功轨迹长度；
  • ot：第 t 步 observation；
  • at：第 t 步 action。

因此，Success Buffer 不是仅保存最终回答，而是保存能够重新恢复和 replay 的完整交互轨迹。

2.3 不是所有成功轨迹都同等重要

论文会计算同一个任务在当前 policy 下的经验成功率：

acc(x) = (1 / G) Σ 1[R(g) = 1]

其中 G 表示该任务的 rollout group 大小。 如果一个任务几乎每次都成功，它已经比较简单； 如果每次都失败，则当前模型可能还无法有效学习。 因此 CRPS 更关注处于模型当前能力边界附近的任务。

2.4 从成功轨迹的 suffix state 开始

假设一条成功轨迹长度为 T，CRPS 选择一个 suffix length k， 从：

t₀ = max(0, T − k)

对应的状态恢复。 

完整成功轨迹：

s0 → s1 → ... → s60 → s70 → s80 → success
                          ↑
                        restore

从 s70 开始：
    ├── rollout 1
    ├── rollout 2
    ├── rollout 3
    └── rollout 4

注意，这些新的 continuation 仍然由当前最新 policy生成， 不是简单复刻原成功轨迹。 因此新的 suffix trajectory 仍然是新的训练数据。

2.5 为什么 suffix length 可以作为 Curriculum 难度？

因为： 

k 小
→ 离终点近
→ 剩余决策步骤少
→ 子任务相对简单

k 大
→ 起点更靠前
→ 剩余决策步骤多
→ 需要更长 Horizon 的规划
→ 更难

因此 CRPS 的 Curriculum 不是人工给任务打 Easy / Hard 标签， 而是通过控制剩余 Horizon 自动形成难度。

2.6 suffix 难度是动态调整的

论文会统计当前模型从某个 suffix state 出发后的 replay success rate：

accreplay(x) = (1/G) Σ 1[R(g) = 1]

随后使用指数移动平均跟踪某个 k 下的经验成功率：

ρ̂k ← (1 − λ)ρ̂k + λ · accreplay(x)

再通过目标成功率区间控制 k： 

如果 replay success rate 太高：
→ 当前 suffix 太容易
→ 增大 k
→ 起点向前移动
→ 任务变难

如果 replay success rate 太低：
→ 当前 suffix 太难
→ 减小 k
→ 起点向终点移动
→ 任务变简单

因此 CRPS 实际使用的是一种online adaptive curriculum， 而不是固定的数据顺序。

2.7 初始难度也根据当前模型能力确定

论文使用任务当前成功率 acc(x) 和轨迹长度 T 来初始化 suffix 长度， 形式上可以表示为：

k₀ = clip( ⌊(βmin + (βmax − βmin)acc(x))T⌋, kmin, kmax )

直觉是： 

任务当前成功率低
→ 从靠近终点的位置开始
→ 给模型较短、较容易的 suffix

任务当前成功率较高
→ 从更靠前的位置开始
→ 增加剩余 Horizon

2.8 CRPS 不会完全替代 Fresh Exploration

训练数据来自两个来源： 

Fresh Exploration
从完整任务初始状态 rollout

+

Curriculum Replay
从 Success Buffer 中的中间 state rollout

这样做是为了避免模型只模仿过去已经发现的少数成功路径。

2.9 实验发现

论文在 ALFWorld、WebShop 等长交互环境中测试， 结果显示相对于直接 full-episode GRPO 和简单 replay， CRPS 能够：

  • 提高任务成功率；
  • 减少一组 rollout 全成功或全失败的极端情况；
  • 让更多训练 batch 产生有效 advantage；
  • 提高长 Horizon 任务上的样本效率。
对当前运筹项目最直接的迁移：

CRPS： 成功轨迹 → suffix state → 当前 policy 重新 rollout → 用 replay success rate 动态控制难度。

可以扩展成： 失败 / 低分轨迹 → 找仍然具有纠偏空间的关键 state → 当前 policy 重新 rollout → 用高质量解比例、平均得分、成功率估计 state difficulty → 动态 Curriculum。

3. Watch Every Step / IPR：用 Monte Carlo Rollout 得到 Step-Level 训练信号

论文： Watch Every Step! LLM Agent Learning via Iterative Step-level Process Refinement

3.1 为什么只看最终 Reward 不够？

假设 Agent 最终成功： 

a1 → a2 → a3 → a4 → a5 → success
                           reward = 1

仅仅根据最终 reward=1， 无法判断中间的 a2、a3 是否本身是好动作。 它们有可能很差，只是模型后来又纠正了。 同理，一条最终失败的 trajectory， 前面的大量动作可能其实是正确的。

因此论文希望估计：

rs(st, at)

即某一个中间 state-action pair 对最终任务结果的长期贡献。

3.2 Step Reward 是怎么获得的？

论文没有人工逐步标注，而是使用 Monte Carlo rollout。 在状态 st 采取动作 at 后， 从这里继续采样 N 条完整 trajectory： 

                    (s_t, a_t)
                   /    |    \
                 τ1     τ2     τ3 ... τN
                 ↓      ↓      ↓
                R1     R2     R3

然后通过最终 outcome reward 的平均值近似 step reward：

rs(st,at) ≈ (1/N) Σ ro(u,e(i))

也就是说：

如果在某个 state 采取某个 action 以后， 后续经常能够得到成功或高 reward， 那么这个 action 的长期价值较高。

3.3 轨迹从哪里来？

IPR 先使用 expert trajectories 对 Agent 进行 SFT， 得到一个基础 scorer / policy。 之后沿 expert trajectory 逐步探索。

假设 expert trajectory 为： 

a1* → a2* → a3* → a4* → ... → success

到第 t 步之前，使用 expert prefix： 

a1* → a2* → ... → a(t-1)*

到第 t 步时，不再强制采用 expert action， 而让当前 Agent 自己产生动作： 

                  s_t
               /       \
        expert action   current action
            a_t*             â_t

之后分别对 expert action 和当前 action 做 Monte Carlo continuation， 得到：

rs(st, at*)
rs(st, ât)

3.4 什么时候构造 Good / Bad Pair？

IPR 并不会因为 current action 和 expert action 不一样， 就简单认为 current action 是错的。 论文要求 current action 在 step-level reward 上明显差于 expert action， 并且最终 outcome 也更差， 才把这对轨迹纳入 contrastive training data。

因此最终可以形成： 

相同 prefix / state：

Chosen:
expert action
→ 高 step reward continuation

Rejected:
current agent action
→ 低 step reward continuation

3.5 最终训练数据是什么形式？

论文构造两类 contrastive dataset。

Step-level dataset

Ds = { (et−1, ewt:n, elt:m) }

表示： 

相同历史 prefix

Winner continuation
vs.
Loser continuation

Outcome-level dataset

Dt = { (u, ew, el) }

即整条成功轨迹与整条失败轨迹的偏好对。

3.6 最终怎么训练模型？

IPR 使用多个损失联合训练：

L = Loutcome-DPO + Lstep-DPO + LSFT

其中：

  • Outcome-DPO：学习整体成功轨迹优于失败轨迹；
  • Step-DPO：学习相同历史下，高价值局部 continuation 优于低价值 continuation；
  • SFT：提高高质量轨迹本身的生成概率。

3.7 实验

论文在 WebShop、InterCodeSQL、ALFWorld 等交互任务上进行测试， 并报告相对于对比方法取得了明显提升。 其最重要的实验意义不是具体提升百分点， 而是证明：

通过从中间 state 多次 Monte Carlo rollout， 可以把原本只有 terminal reward 的 trajectory 转换成 step-level supervision。
对当前项目的直接迁移：

找到关键 state s180 后： s180 → rollout N 次 → 得到多个不同最终 score 然后不仅可以判断“这个 state 难不难”， 还可以进一步估计： 某个 action 之后的 expected downstream score。

于是可以生成： (state, good action, bad action) 或者： (state, good continuation, bad continuation) 用于 Preference / DPO / Process Reward Model。

4. PaTR：不从头重复 Rollout，而是在有价值的中间状态构建 Rollout Tree

论文： Process Reward Informed Tree Rollout for Effective Multi-Turn RL

4.1 传统 Rollout 为什么浪费？

传统 group rollout： 

task x
├── complete rollout 1
├── complete rollout 2
├── complete rollout 3
├── complete rollout 4
└── complete rollout 5

每条轨迹都从起点重新生成。 对于几百轮甚至更长的 trajectory， 不同 rollout 前面可能有大量重复或相似决策， 这部分计算实际上被反复浪费。

4.2 PaTR 把 Rollout 组织成一棵树

                 s0
                  ↓
                 s1
                  ↓
                 s2
             /    |    \
           s3a   s3b   s3c
           / \          |
         ... ...       ...

方法维护一组 active branches。 每一轮先让每个 branch 向前生成 K 个 interaction steps， 然后对新的 partial trajectory 打 process score：

sit = Sφ(x, τit) ∈ [0,1]

4.3 每个中间节点会被分为三类

Expansion

如果 partial trajectory 的 process score 很高， 从这个状态生成多个 child branches：

τit,m ~ πθ(· | x, τit) 
              high-value state
               /     |     \
          branch1 branch2 branch3

Survival

如果当前分支得分一般，但没有明显错误， 不进行额外 branching， 继续执行 K 步后再重新评价。

Pruning

如果：

sit < median(sjt) − α

则该分支会提前停止。 另外，如果连续 Θ 轮重复同一动作， 也可以被认为是 degenerate branch 并停止。

4.4 被 Prune 的失败轨迹不会被删除

这是 PaTR 很值得借鉴的一点。 被提前停止的 trajectory 仍然加入 completed trajectory set： 

bad branch
↓
early stop
↓
保留
↓
作为 negative trajectory
参与 group-relative RL

论文实验对比了： 

Best-n：
只保留表现好的 branch

vs.

Keep-All：
连低质量 / 被 prune 的 branch 也保留

结果说明，失败 branch 仍然能够提供有价值的 reward contrast。 也就是说：

失败 trajectory 不一定应该丢弃， 它可以作为 relative learning 的 negative sample。

4.5 Process Scorer 怎么来？

PaTR 不强制使用一种 scorer， 可以来自：

  • 启发式任务进度；
  • 已有 reward；
  • 距离目标的估计；
  • 预训练 Process Reward Model；
  • LLM Judge。

对于你的运筹任务，可以用更可靠的结构化指标替代通用 LLM Judge，例如：

  • 当前剩余资源；
  • 容量 slack；
  • 时间窗 slack；
  • remaining demand / remaining capacity；
  • best-achievable objective；
  • 是否还存在 feasible completion。

4.6 Rollout Tree 的超参数

论文实验中会控制：

  • K：多久对 partial trajectory 重新打一次分；
  • M：一个高价值节点生成多少 child branches；
  • top-k：哪些 active branches 获得扩展机会；
  • α：Pruning margin。

论文在部分 ablation 中使用了类似： 

branch factor M = 2
scoring interval K = 13
top branches = 2

并发现 branch factor 并非越大越好。 branch 太多会削弱 process scorer 对计算预算的聚焦作用。

对当前项目尤其重要：

你现在想到的是： 关键状态 s180 → 完整 rollout 10 次 → 每条继续跑剩余 150 轮。

如果这很贵，可以改成 PaTR 式： s180 → 每个 branch 先跑 10~20 步 → 评估 partial trajectory → 高潜力 branch 再分叉 → 普通 branch 继续 → 明显差的 branch 提前停止。

这样可以显著减少在已经明显走坏的轨迹上继续消耗数百万 Token。

5. AgentRx：如何在长失败轨迹中定位 Critical Failure Step

论文 / 项目： AgentRx: Diagnosing AI Agent Failures from Execution Trajectories

5.1 它关注的不是最终报错，而是第一个不可恢复错误

AgentRx 定义 Critical Failure Step：

一条失败 trajectory 中， 第一个使后续任务无法恢复到成功状态的关键错误步骤。

例如： 

step 70    正常
step 71    正常
step 72    正常
step 73    ← Critical Failure Step
step 74
step 75
...
step 190   ← 最终失败显现

因此最终失败表现的位置不一定是真正原因。

5.2 Trajectory Normalization

不同 Agent 框架日志格式差异很大， AgentRx 首先将： 

LLM message
tool call
tool output
agent action
system event

统一转换为标准化的 intermediate representation。

5.3 Constraint Synthesis

AgentRx 根据： 

Tool Schema
+
Domain Policy

自动产生一组可以检查轨迹行为是否正确的 constraints。 例如：

  • 调用某 API 前必须满足某前置条件；
  • 参数必须符合 schema；
  • 只有工具真正返回某结果，Agent 才能声称该事实；
  • 某些破坏性操作必须获得确认。

5.4 Guarded Step-wise Evaluation

并不是每个 constraint 每一步都检查。 每个 constraint 都有适用条件， 只有满足 guard condition 时才执行验证。 最终形成类似： 

step 12:
constraint A → pass

step 13:
constraint B → pass

step 14:
constraint C → violation
evidence: ...

step 15:
constraint D → violation
...

5.5 最终 Critical Step 如何判断？

LLM Judge 不直接从零阅读整个 raw trajectory， 而是结合： 

标准化 trajectory
+
constraint violation log
+
failure taxonomy

定位最早、最具有因果意义的 failure step。

5.6 Benchmark

论文构建了人工标注失败轨迹集， 其中包含不同交互环境， 并人工给出：

  • Critical Failure Step；
  • Failure Category；
  • 对应根因。

Microsoft 报告，相对于直接 prompting baseline， AgentRx 在 critical step localization 和 root-cause attribution 上均取得明显提升。

你的运筹场景可以比 AgentRx 更简单、更可靠：

如果你能够从中间 state 调用 solver， 可以直接测试： F(s_t) = 是否还存在 feasible completion 以及： V*(s_t) = 从当前 state 出发仍然能够取得的最好 objective

那么你可以用真实运筹约束和 solver 直接定位 feasibility cliff / quality cliff， 不一定需要依赖 LLM Judge。

6. DAPO：用当前模型的 Rollout 分布定义“经验难度”

论文： DAPO: An Open-Source LLM Reinforcement Learning System at Scale

6.1 Dynamic Sampling 的出发点

DAPO 发现，对于 group-relative RL， 如果同一 prompt 下的 G 个 rollout 全部正确： 

1 1 1 1 1 1 1 1

或者全部错误： 

0 0 0 0 0 0 0 0

组内 reward 都没有差异， 因此 advantage 信号非常弱甚至退化。

6.2 它实际怎么做？

DAPO 会持续 oversample prompts， 直到获得足够多满足：

0 < #{correct responses} < G

的 rollout groups。 也就是说： 

全会的
→ 暂时没必要重点训练

全不会的
→ 当前模型没有区分信号

部分会、部分不会的
→ 当前最有学习价值

6.3 这本质上就是 Model-Aware Difficulty

一个任务是否困难，不是它的固定属性， 而取决于当前 policy。

迁移到你的场景：

st → {τ₁, τ₂, ..., τK}

可以定义：

pquality(s) = # {R ≥ Rtarget} / K

例如：

状态 10 次 Rollout 当前经验难度
s1 10 次全部高分 太容易
s2 8 次高分 较容易
s3 5 次高分 Learning Frontier
s4 2 次高分 困难但仍有学习信号
s5 0 次高分 当前可能过难

6.4 对 Curriculum 的直接意义

因此不建议简单： 

Easy
→ Medium
→ Hard
→ Very Hard

更合理的是： 

当前模型大量成功
→ 降低采样

当前模型成功率中等
→ 提高采样

当前模型完全失败
→ 暂时降低采样
→ 等模型能力提高后再加入
Curriculum 难度最好是 Policy-Dependent 的， 而不是一次性静态标注。

7. SPEAR：高质量轨迹进入 Replay Buffer，持续重复利用

论文： Learn the Ropes, Then Trust the Wins: Self-imitation with Progressive Exploration for Agentic Reinforcement Learning

7.1 为什么需要 Replay Buffer？

在稀疏 reward 的 Agent 环境里， 模型偶然发现一条成功轨迹可能非常昂贵。 如果： 

成功 trajectory
→ 用一次做 gradient update
→ 直接丢弃

会浪费很多已经得到的高价值经验。 因此 SPEAR 保存高价值 trajectory。

7.2 Buffer 中保存什么？

可以抽象为：

D = {(τj, Rj, Âj)}

也就是轨迹、reward 和 advantage。 尤其重点保留 positive-advantage trajectory：

Âj > 0

7.3 为什么不能一开始就大量 Replay？

如果训练早期模型偶然产生少量成功轨迹， 然后反复 self-imitation： 

少量成功经验
↓
大量 replay
↓
policy entropy 快速下降
↓
过拟合少数行为模式
↓
模型停止探索其他可能策略

因此 SPEAR 使用 progressive curriculum。

7.4 Early Stage 与 Late Stage 不同

8. AgentGym-RL / ScalingInter-RL：最直接的 Horizon Curriculum

这类方法不分析每条 trajectory 的细粒度质量， 而是直接控制允许交互多少轮。 例如： 

训练前期：
最多 10 turns

↓

中期：
最多 20 turns

↓

后期：
最多 30 turns

核心思想是：

模型先掌握短 Horizon 的局部决策， 再逐渐学习更长 Horizon 的规划和信用分配。
你可以把它和 CRPS 合并：

不是简单： 10 turns → 20 turns → 30 turns 而是： 关键状态附近 → remaining horizon = 20 更早的关键状态 → remaining horizon = 50 更早的位置 → remaining horizon = 100+ 最后 → 完整任务。

10. Critical State 到底怎么定义？

建议不要把“关键节点”定义成主观判断， 而定义成：

从该状态附近改变决策， 会显著改变最终可行性或最终 objective 的状态。

10.1 硬失败：Feasibility Cliff

定义：

F(st) = 1，如果从 st 仍存在 feasible completion； 否则为 0。

如果： 

s180 → feasible
s190 → feasible
s200 → feasible
s210 → infeasible

那么 200～210 是关键区间。 进一步可以二分搜索： 

s205 ?
s207 ?
s208 ?

找到： 

F(s207) = 1
F(s208) = 0

则： 

s207
→ 原 action
→ s208
→ 不可恢复

这里真正适合当 rollout 起点的是s207， 而不是已经硬失败的 s208。

10.2 低分成功：Quality Cliff

对每个中间 state 求：

V*(st) = 从当前 state 出发仍然能够达到的最好 objective

如果： 

round 100: V* = 96
round 130: V* = 95
round 150: V* = 94
round 160: V* = 79
round 170: V* = 77

则 150～160 是明显的 quality degradation region。 可以定义：

Δt = V*(st) − V*(st+1)

Δt 突然增大时， 说明该 action 消耗了大量未来优化潜力。

10.3 Counterfactual Improvement

对候选 state st 重新 rollout： 

原 continuation：
score = 55

从 s_t 重新 rollout：
best score = 92

可以定义：

Improvement(s) = Rbest reroll − Roriginal continuation

Improvement 很大的 state， 意味着：

原 trajectory 从这里以后存在很大的纠偏空间。

11. Criticality 与 Difficulty 必须分开

11.1 Criticality：这个 State 是否值得生产训练数据？

例如：

C(s) = Rbest reroll − Roriginal 
原 trajectory：55
重新 rollout 最好：94

Criticality / Improvement = 39

说明从这个 state 开始重新训练很有价值。

11.2 Difficulty：当前模型从这里开始有多难？

可以定义目标质量阈值 Rtarget：

D(s) = 1 − P(R ≥ Rtarget | s)

例如： 

s1：
10 次 rollout
8 次 ≥ 90
→ easy

s2：
10 次 rollout
5 次 ≥ 90
→ medium

s3：
10 次 rollout
2 次 ≥ 90
→ hard

s4：
10 次 rollout
0 次 ≥ 90
→ currently too hard
Criticality 决定： 这个节点值不值得拿来生产训练数据。 Difficulty 决定： 这些训练数据应该放在 Curriculum 的哪个阶段。

12. 从 Critical State 具体怎么生产训练轨迹？

假设已经找到： 

critical state = s180

先保存完整可恢复环境状态：

  • 已经完成的任务；
  • 剩余任务；
  • 资源使用情况；
  • 约束状态；
  • 当前 objective；
  • 任何后续求解需要的环境信息。

然后从相同 state 多次 rollout： 

s180
├── rollout 1 → score 94
├── rollout 2 → score 88
├── rollout 3 → score 71
├── rollout 4 → score 54
├── rollout 5 → fail
└── rollout 6 → score 91

每条 trajectory 至少保存： 

source_state_id
source_trajectory_id
start_step

state-action-observation sequence

final_feasible
final_score
termination_reason

trajectory_length
generator_policy_version
random_seed

这样同一个 state 就形成了一组具有质量差异的数据。

13. Rollout 产生的数据最终怎么训练模型？

13.1 SFT

选择最高质量 trajectory： 

Input:
state s180

Target:
94 分 trajectory

如果 trajectory 太长， 可以只使用： 

state
→ 最优下一步 action

或者：

state
→ 未来 5~20 步高质量局部 trajectory

13.2 Preference / DPO

同一个 state 天然可以形成： 

Prompt:
state s180

Chosen:
94 分 continuation

Rejected:
54 分 continuation

即：

(st, τ⁺, τ⁻)

这种数据尤其适合运筹问题， 因为很多状态不一定只有唯一正确 solution， 更适合学习“哪个方案相对更好”。

13.3 Process Reward / Value Data

将： 

state
action
downstream rollout score

作为监督：

Q(st, at) ≈ E[R | st, at]

可以训练模型预测某个动作对未来最终结果的长期影响。

13.4 RL / GRPO Start State

中间状态本身也可以不固化成答案， 而作为训练环境的起点： 

reset environment to s180
↓
当前 policy rollout K 条
↓
最终 objective 作为 reward
↓
组内计算 advantage
↓
更新 policy

这与 CRPS 的核心思想最接近。

14. Curriculum 应该怎么组织？

第一版可以使用：

pquality(s) = P(R ≥ Rtarget | s)

作为状态难度估计。

高质量 Rollout 比例 含义 建议
90%～100% 已经基本掌握 降低采样比例
60%～90% 较容易 可用于 Curriculum 早期
30%～60% Learning Frontier 重点训练
5%～30% 困难但仍有学习信号 模型提升后逐渐增加
0%～5% 当前可能过难 暂时降低采样
Curriculum 最重要的不是“从最低难度机械排到最高难度”， 而是持续把训练预算放在当前模型能力边界附近。

随着模型能力提高，需要重新 rollout， 因为： 

原来 success rate = 20%
↓
模型变强
↓
重新 rollout
↓
success rate = 70%

这个 state 的难度标签已经发生变化。 因此 difficulty 应该是动态的。

15. 针对当前场景的第一版实验设计

为了避免第一版工程过重，可以先做最小闭环。 

Step 1
从现有失败 / 低分长轨迹中
人工 + 规则选择 20~50 个 candidate states


Step 2
每个 state 当前模型 rollout K 次

例如：
K = 8


Step 3
保存：

final feasibility
final score
trajectory length
termination reason


Step 4
统计：

success rate
high-quality rate
mean score
best score
score variance
improvement over original trajectory


Step 5
过滤：

没有 improvement 的 state
→ 降低优先级

100% 高分的 state
→ 太简单，降低采样

部分高分、部分低分的 state
→ 核心训练状态

0% 高分的 state
→ 当前过难，暂时降低采样


Step 6
生成训练数据：

best trajectory
→ SFT

best vs bad
→ Preference

state checkpoint
→ RL


Step 7
模型训练一轮以后重新 rollout

重新估计：
difficulty
success rate
score distribution

然后更新 Curriculum

16. 如果 Rollout 成本特别高：推荐使用 Tree Rollout

如果： 

一个 critical state
→ 剩余 200 轮
→ 每条 continuation 数百万 Token

那么每个 state 完整 rollout 8～16 次可能太贵。 可以借鉴 PaTR： 

critical state
↓
生成 4 个 branch
↓
每个先跑 10~20 轮
↓
计算 partial quality

高潜力：
→ 继续
→ 甚至继续 branch

中等：
→ 保留继续

明显差：
→ early stop
→ 保存为 negative

这样不必让明显已经变差的 trajectory 继续跑完全部剩余 Horizon。

18. 当前方案可概括为什么方法？

可以暂时概括为：

Critical-State-Guided Branching Rollout for Curriculum Data Construction

核心过程：

失败 / 低分超长 trajectory → 识别高影响、仍可恢复的 critical states → 从这些 state 进行 branching rollout → 用 rollout distribution 估计 policy-dependent difficulty → 将高低质量 continuation 转成监督 / preference / RL 数据 → 根据模型能力动态更新 Curriculum。

20. 最终建议

结合当前已有超长失败 / 低分轨迹，以及“可以从中间状态重新求解”这一非常有利的条件， 比较推荐的第一版方法是：

1. 轨迹压缩成结构化 state-action 序列 2. 每隔若干轮建立 checkpoint 3. 用 solver / constraint checker 估计： - 是否仍可行 - best-achievable objective 4. 找： - Feasibility Cliff - Quality Cliff 5. 在这些区域局部加密搜索 得到少量 Critical States 6. 从每个 Critical State rollout K 次 7. 记录： - success rate - high-quality rate - mean score - best score - variance - improvement 8. Criticality： 判断该 state 是否值得生产数据 9. Difficulty： 判断该 state 对当前 policy 有多难 10. 数据转换： - Best trajectory → SFT - Best vs Bad → Preference / DPO - state-action-score → Process / Value Model - checkpoint → RL Start State 11. Curriculum： 优先训练当前模型“部分会、部分不会”的 state 12. 模型能力提升后重新 rollout， 动态更新 Difficulty 与采样比例
最核心的逻辑可以压缩为一句话：

不是直接把失败长轨迹拿去训练， 而是把失败轨迹当作“寻找高价值训练状态的矿藏”； 从其中找到仍有纠偏空间的关键状态， 再通过 branching rollout 生成真正具有监督价值和难度信息的新轨迹。
